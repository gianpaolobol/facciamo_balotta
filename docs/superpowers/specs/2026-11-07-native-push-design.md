# Push native facoltative

Estendere la casella interna con avvisi generici iOS/Android usando il servizio Expo Push gratuito. Nessun invio reale, deploy, nuova chiave, piano o build firmata durante l'implementazione. Tutto disattivato per default, nessun cron configurato.

Consenso solo dopo pulsante esplicito su telefono fisico; nessuna richiesta automatica all'avvio. Token Expo ottenuto con il projectId EAS reale. Titolo `Facciamo Balotta`, testo `Hai nuovi aggiornamenti nell’app.`, dati solo `{screen:'updates'}`, TTL300 secondi. Nessun nome, contenuto chat, ID personale o del dominio sul blocco schermo. Tap apre solo l'app; i contenuti richiedono sessione corrente.

Registrazione autenticata POST `/api/push/device` con `{installationId,installationSecret,token,projectId}`; stato GET stesso percorso con parametri assenti restituisce `{enabled:boolean}` per sessione corrente; revoca POST `/auth/push/disable` con `{installationId,installationSecret}`, risposta generica `{ok:true}`. ID UUID e segreto esadecimale64 generati e conservati in SecureStore; prova hashata nel server. Token cifrato AES256GCM con chiave server64hex, hash univoco anti-appropriazione. Stessa installazione/prova può cambiare proprietario; installazioni diverse non possono appropriarsi di token già registrati. Al cambio account/disconnessione revocare la registrazione; session hash FK cascade impedisce invii dopo logout, revoca Apple o eliminazione account. La consegna già accettata dal provider non è revocabile, perciò il testo resta generico.

`pushEnabled` richiede flag esplicito, projectId UUID reale, chiave cifratura e access token Expo enhanced-security sul server. Massimo5 dispositivi/account,100 tentativi globali/UTCgiorno,20/dispositivo/giorno, intervallo minimo5minuti. Prenotazione SQL atomica, tentativi falliti contati, nessuna duplicazione concorrente. Stato ticket non equivale a consegna; ricevute verificate dopo15minuti, scadenza24ore; DeviceNotRegistered revoca solo la versione di registrazione interessata. Ledger limitato agli ultimi7giorni, contatori preservati quando si eliminano dispositivi/account. Nessuna notifica storica al consenso; nessun push per notifiche lette/non più autorizzate, sessioni scadute o profili non idonei.

Worker scheduled handler predisposto ma nessun trigger pubblicato. Dispatcher massimo5 invii per esecuzione, timeout10s/provider, URL Expo fisso e fetch iniettato nei test. Tutte le verifiche usano account sintetici e provider simulato; un export non prova l'arrivo su telefono. Restano esterne configurazione APNs/FCM/EAS e prova fisica iOS/Android.
